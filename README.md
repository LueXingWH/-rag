# 校园资料问答助手 · RAG Demo

> 一个**零依赖、可引用、会拒答**的检索增强生成（RAG）系统。
> 把学校的制度文件（推免、奖学金、实验室、图书馆、竞赛、学籍、生活服务）丢进去，
> 就能用大白话提问，得到**带出处的回答**；资料里没有的，它明确说"不知道"。

**半天做完，但不是"调一次 API"**：检索层是自己写的（BM25 + 字符 n-gram TF-IDF + RRF 融合），
拒答阈值是靠评测集标定出来的，所有指标都能一条命令复现。

> 📖 **第一次看这个项目、或者想弄懂代码怎么运作？** 三份文档，按你的基础选一份就够了：
> - 有 Python 基础（看得懂函数/`if`/`for`）→ [`docs/代码走读-有Python基础版.md`](<docs/代码走读-有Python基础版.md>)
>   —— **不讲语法，只讲数据怎么在模块间流动、每个判断为什么存在**，30 分钟。
> - 完全零基础 → [`docs/项目全书-图解.md`](<docs/项目全书-图解.md>)（流程图为主干，30 分钟）
> - 想要最啰嗦的逐行讲解 → [`docs/项目全书-逐行讲解.md`](<docs/项目全书-逐行讲解.md>)（约 2.1 万字，当手册查）

## 1. 三分钟跑起来

```powershell
# ① 离线模式（不需要网络、不需要任何第三方包，Python 3.8+ 即可）
python ask.py --info                  # 自检：语料、配置、可选能力
python ask.py "挂科重修后还能申请推免吗？"   # 单次提问
python ask.py --web                   # 浏览器 Demo（推荐现场演示用）
python ask.py --eval                  # 跑 22 题离线评测，打印指标
python demo_check.py                  # 演示脚本自检：确认上台要问的问题条条都对
python sweep.py                       # 参数网格搜索（用指标挑参数，而不是凭感觉）
python bench.py                       # 消融实验：每项改动到底有没有用
python calibrate.py                   # 只看拒答阈值的扫描曲线

# ② 联网增强（可选：检索结果交给大模型组织成自然语言）
$env:DEEPSEEK_API_KEY = "sk-xxxx"     # 见下方"可选增强"
python doctor.py                      # 接不上时先跑这个：逐项体检并直接给结论
python ask.py --check-llm --llm       # 只看"能不能拿到答案"这一环
python ask.py --web --llm             # 默认开大模型
python ask.py --web                   # 也可以：起来后在页面上用开关随时切换（配了 key 才可拨）
```

Windows 用户可直接双击 `run_web.bat` 一键起服务。它**先告诉你这个窗口能不能看到 `DEEPSEEK_API_KEY`**
（含末 4 位，只说有没有、不打印完整 key），再让你选：

- **[1] 默认离线** —— 但页面上的「使用大模型」开关照常可用（配了 key 时）
- **[2] 默认开大模型** —— **启动前先跑一次真实连通性自检**（`--check-llm`），
  失败会当场打印原因（key 无效 / 余额不足 / 连不上），并问你要不要退回离线；
  没检测到 key 时**交给 Python 的中文引导**（`--ask-key`）：列出在哪复制、
  提醒**右键粘贴**（cmd 里 Ctrl+V 常常没反应）、回显 `sk-abc...7890` 掩码让你核对尾 4 位、
  非 `sk-` 开头会警告，最后给出 `setx` 永久保存的命令。
  注意这里**不再用 .bat 自己的 `set /p`**：批处理必须纯 ASCII，只能写英文提示，
  而这恰恰是最需要说清的一步；改成 Python 读入后，key 直接落在**将要跑服务的那个进程**里，
  连"环境变量只在某个窗口有效"这类问题一起绕开了

> ⚠️ 最常见的坑：在 PowerShell 里 `$env:DEEPSEEK_API_KEY="sk-..."` 只影响**那一个窗口**；
> 从资源管理器**双击** bat 会新开一个进程，看不到它。要么在同一个 PowerShell 窗口里跑
> `.\run_web.bat`，要么用 `setx` 后关掉窗口重开，要么就用上面的选项 [2] 直接粘。
>
> 另外这个 bat **必须保持纯 ASCII + CRLF 行尾**（cmd.exe 按字节偏移读批处理，中文或 LF 会让它
> 从词中间读起，报一堆"`'indow:'` 不是内部或外部命令"）。`tests/test_regressions.py`
> 里有三条测试专门盯着这件事。

**没有 API key 会怎样？** 自动降级为"离线抽取式回答"：从资料里挑出最相关的原句、
原样摘录并标注出处。**永不报错、永不断演示**——这是刻意的设计取舍。

## 2. 它解决了什么问题

普通做法是"把问题丢给大模型"，两个致命问题：

| 问题 | 本项目怎么做 |
| --- | --- |
| **幻觉**：模型编造不存在的政策条款 | 提示词强约束 + 强制标注 `[n]` 引用 + **检索证据不足直接拒答** |
| **不可核对**：你无法验证它说的是真是假 | 每条结论都能点开原文段落；UI 里引用可直接跳转到原文块 |

一句话概括技术方案：**"先检索、后生成、带引用、可拒答"**。

## 3. 架构与数据流

```
                    ┌──────────────────────────── 离线可跑（无网络、无第三方包） ───────────────────────────┐
提问 ──▶ 分块语料 ──▶ │ BM25 词法通道（标题加权 + 同义词扩召回）        ┐                          │
        (63 块/2 篇) │ 字符 3-gram TF-IDF 向量通道（余弦相似度）      ├─▶ RRF 融合 ─▶ 置信度闸门 │──▶ 回答
                    │ [可选] 语义 embedding 通道（bge-m3 等）        ┘                │          │
                    └───────────────────────────────────────────────────────────────┼──────────┘
                                                                                    │
                                      拒答（证据不足）◀──────────────────────────────┤
                                                                                    ▼
                                                              LLM 生成（严格接地）或 抽取式降级
```

| 文件 | 职责 | 关键实现 |
| --- | --- | --- |
| `campus_rag/text.py` | 中英混合分词 | CJK **bigram + unigram**（Lucene CJKBigramFilter 的 outputUnigrams 做法）+ 英文轻量词干化 + 停用词 |
| `campus_rag/data.py` | 加载与分块 | 标题路径切块 + 句子滑窗 overlap + **表格表头回填** |
| `campus_rag/retriever.py` | 检索 | 手写 BM25（k1=1.2, b=0.75）、TF-IDF 向量、RRF 融合、片段抽取 |
| `campus_rag/engine.py` | 答案生成 | 置信度闸门 + 接地提示词 + 抽取式降级（BM25 机制打分选句） |
| `campus_rag/llm.py` | LLM/Embedding 客户端 | 纯 `urllib` 调 OpenAI 兼容接口，错误可分类可降级 |
| `campus_rag/web.py` + `ui.html` | Web Demo | 标准库 `http.server`，单文件前端，无构建步骤 |
| `campus_rag/evaluate.py` | 评测 | Hit@k / MRR / 拒答准确率 / 硬答率 / 关键事实覆盖率（**拒答一律计 0 覆盖**） |
| `sweep.py` | 参数网格搜索 | 扫 (阈值 × evidence_k)，按"硬答率→拒答准确率→覆盖率"排序选参数 |
| `bench.py` | 消融实验 | 逐个验证改动（如抽取式候选块数）是否真的提升指标；**严格 / 端到端双口径** |
| `tests/test_regressions.py` | 回归测试 | 零依赖 `unittest`，把修过的 bug 逐条钉住（同义词死代码、拒答刷覆盖率、bench 双口径、`:s` 恒真） |
| `doctor.py` | 接入体检 | 一条命令查完 6 环：环境变量 → 配置解析 → DNS/TCP → `/models` → `/chat/completions` → 旧服务端口；末尾直接给结论 |
| `demo_check.py` | 演示自检 | 把上台要问的问题跑一遍，防止改动后悄悄退化 |
| `calibrate.py` | 阈值曲线 | 打印"阈值 vs 漏答率 vs 硬答率"的完整权衡曲线 |
| [`docs/代码走读-有Python基础版.md`](<docs/代码走读-有Python基础版.md>) | **★ 有 Python 基础先读这个** | 不讲语法，只讲数据怎么流动 + 每个判断为什么存在；约 0.4 万字，30 分钟 |
| [`docs/项目全书-图解.md`](<docs/项目全书-图解.md>) | 零基础·图解版 | 10 节图解 + 实跑数据 + 调试验错手册；约 0.5 万字，30 分钟 |

## 4. 实测指标（可复现）

`python ask.py --eval`，22 题评测集（16 题可答 / 6 题故意不可答），纯离线：

| 指标 | 数值 | 含义 |
| --- | --- | --- |
| **Hit@3** | **100%** | 答案所在文档被召回的比例（检索是这个系统的上限） |
| **Hit@1** | **81.2%** | 正确文档排在第一位的比例（13/16） |
| **MRR** | **0.896** | 平均倒数排名 |
| **拒答准确率** | **77.3%** | "该答/该拒"判断正确的比例 |
| **硬答率（幻觉风险）** | **0.0%** | 资料里没有却硬答的比例 —— 最关键的安全指标（6 题应拒答题全部正确拒答） |
| **关键事实覆盖率** | **62.5%** | 回答中包含期望数字/术语的比例（**拒答 = 计 0**，见下方口径修正） |
| 漏答率（过度保守） | 31.2% | 有资料却拒答：多为"复合问句/大白话提问"（见 §7 局限） |
| 检索+回答延迟 | **2–3 ms / 题（p50）** | 纯词法检索，无网络往返；随机器负载抖动，别当基准测试看 |

> 上表由 `python ask.py --eval` 在 2026-10-06 实测得出，语料为 `data/corpus/`（2 篇 / 63 块），
> 逐题明细见 `data/logs/eval_report.json`。**改动检索逻辑后请重跑本命令，不要手改这张表。**
>
> **口径修正（2026-10-06）**：关键事实覆盖率原报 81.2%，那是**被 bug 抬高的**——拒答正文里会
> 原样引用检索到的候选片段，而覆盖率是在整段回答上做词面匹配，于是 `n09`/`n11`/`n14`
> 三条**该答却拒答**的题反而记了 100%。现在拒答一律计 0，真值是 **62.5%**。
> （顺带一句：Hit@1 也恰好是 81.2%，两者**曾经的数值相同纯属巧合**，毫无关系。）

**四次迭代的真实轨迹**（下表数字是在**早期 7 篇语料 / 旧版评测集**上测的，
保留为过程记录——它记录的是"我当时的判断顺序"，不是当前可复现的指标；当前指标见上表）：

| 版本 | 改了什么 | 拒答准确率 | 硬答率 | 关键事实覆盖率 |
| --- | --- | --- | --- | --- |
| v0 朴素覆盖率 | 用"命中词数/总词数"当置信度 | 72.7% | **83.3%** ← 几乎来者不拒 | — |
| v1 IDF 加权 | 覆盖率按 IDF 加权，"什么/多少"不再算证据 | 81.8% | **0.0%** | ~70% |
| v2 表格表头回填 | 修分块缺陷（"可借册数""借期"原本只在表头） | 86.4% | 0.0% | ~75% |
| **v3 单字索引 + 抽取式重写 + 参数网格搜索** | **补 unigram 通道、句子打分改用 BM25 机制、用 sweep.py 挑参数** | 81.8% | **0.0%** | **82.3%** |

> 注意 v3 是**用指标做决策**的一轮，也是最有价值的一轮：
> 我先凭直觉把"抽取式候选块数"放宽到 5，指标反而从 79.3% 掉到 69.0%——
> `bench.py` 的消融实验直接否掉了这个改动，最终定回 3 块。
> **"看起来更周到"的改动，必须让指标说话。**
>
> ⚠️ 上面这组数字用的是**修 bug 之前**的覆盖率口径（拒答也能刷分）。在修好的口径下重跑
> `bench.py`：2 块 53.8% → 3 块 **65.4%** → 4/5/6 块仍是 65.4%。
> 结论仍然成立（**3 块是拐点**），但"放宽到 4-6 块会更差"这件事在当前语料上**已不复现**——
> 它当年更可能是被那个刷分口径放大的。留在这里是因为**过程**比结论更值得讲。

## 5. 六个关键设计决策（面试重点）

1. **离线优先（offline-first）**：检索与演示不依赖网络和任何第三方包。
   权衡：放弃了 jieba/向量库的精度上限，换来"任何机器上必定跑得起来"。
   用 CJK bigram 替代词典分词——这也是 Lucene `CJKBigramFilter` 的官方做法。

2. **双通道检索 + RRF 融合**：BM25 擅长精确术语（"8000 元""30 天"），
   字符 n-gram TF-IDF 擅长模糊改写。RRF 只用**排名**不用分值，
   天然规避两条通道分数量纲不一致的问题。

3. **拒答闸门（abstention gate）前置于生成**：证据不足时不把材料送给模型，
   从源头切断幻觉。阈值不是拍脑袋，是用 `calibrate.py` 扫出来的（宁可漏答，不可硬答）。

4. **IDF 加权的置信度，而不是朴素覆盖率**：中文 bigram 下"什么/时候/多少"命中毫无证据力。
   朴素覆盖率把虚词当证据，导致"没料也硬答"——这是 v0 → v1 的核心修正。
   另外两个校准项：**稀有词惩罚**（全语料只出现 1 次的词命中多半是巧合）、
   **OOV 惩罚**（查询里语料从未出现的概念占比越高，越该拒答）。

5. **表格表头回填**：原始 Markdown 表格行里根本没有"可借册数""借期"这些词——
   它们全在**表头**。表头与数据行被切到不同块，检索就必然漏掉这类问题。
   修法：识别连续表格 → 把表头拼进每一行文本。这一处改动直接把 Hit@1 推到了 100%。

6. **LLM 是可选、可失败的薄层**：`urllib` 直连、错误分类（401/402/429/超时）、
   失败即降级到抽取式回答。把不确定性隔离在边界内，主流程永不崩。

## 6. 可选增强（联网 / 更强效果）

### 6.1 大模型生成（把摘录变成通顺回答）

```powershell
$env:DEEPSEEK_API_KEY = "sk-xxxx"
python ask.py --web --llm                      # 默认模型 deepseek-flash
python ask.py --llm --model deepseek-v4-pro    # 换更强的模型
```

- 兼容任何 OpenAI 协议服务：改 `CAMPUS_RAG_BASE_URL` / `CAMPUS_RAG_MODEL` 即可。
- DeepSeek 现役模型为 `deepseek-flash` / `deepseek-v4-pro`
  （旧的 `deepseek-chat` / `deepseek-reasoner` 已下线，模型名走配置不硬编码）。
- 成本量级：单次问答约 2k 输入 + 0.3k 输出 token。按 flash 未命中输入 1 元/百万、
  输出 4 元/百万计，**单次 ≈ 0.003 元**，100 次问答不到 4 毛钱。
- 自带 `python ask.py --info` 会调 `/models` 自检 key 是否可用。
  如果它显示"已检测到 API key，但本次没启用"，说明你漏了 `--llm`——**只设 key 不会自动启用**
  （会自动启用的只有 `CAMPUS_RAG_API_KEY` 这个名字）。
  加 `--offline`（或设 `CAMPUS_RAG_OFFLINE=1`）时自检会**跳过**，一个网络请求都不发。
- Web 页面右上角的"大模型生成"徽章显示的是**真实开关**，关着时会直接写明原因
  （`未配置 API key` / `未加 --llm` / `强制离线`），不会再出现"徽章说开、回答却降级"的矛盾。
- **页面上有「使用大模型」开关**（输入框上方），**只在配了 API key 时可用**；
  没配 key 或加了 `--offline` 时它是灰的，并写明原因。
  **"配了 key"还不够**：服务启动时会真发一次 `/models`，**只有探测成功开关才可拨**——
  否则 key 写错时开关照样能点，然后每题静默降级（"按钮能用但根本没用"）。
  探测失败时开关显示"不可用"并带上真实原因（`HTTP 401…` / `连不上…`），
  旁边还有「重新检测」——启动那一下碰上网络抖动，不必为它重启整个服务。
  开关是**按题生效**的（`engine.answer(use_llm=…)`，不改进程配置），
  状态只在**本次页面会话**内有效：刷新就回到服务端默认。
  **刻意不持久化**——曾经把它存进浏览器，结果上次随手关掉之后，下次用 `--llm` 启动时
  那个"关"会把服务端的"开"悄悄压掉（"我明明选了默认开，页面还是关"）。
  因此**起服务时不必再纠结加不加 `--llm`**：`python ask.py --web` 起来后随手拨一下就行；
  `--llm` 只决定"默认是开还是关"。
- **思维链默认关闭（`llm_thinking="disabled"`），这是刻意的**：DeepSeek V4 的 thinking
  **默认开启**且 effort 默认 `high`，思维链走 `reasoning_content`、答案走 `content`；
  而本项目 `max_tokens=700` 是留给"结论 + 依据"的，思维链一开就把它吃光，
  `content` 返回空串。另外 thinking 模式下 `temperature` 会被**静默忽略**——
  等于本项目设的 `temperature=0.2` 从来没生效过。
  想开回来：`CAMPUS_RAG_THINKING=enabled`（不认这个扩展字段的第三方网关设 `omit`）。
- **真出问题时跑这条**：
  ```powershell
  python ask.py --check-llm --llm
  ```
  它会**真的发一次请求**并打印 `finish_reason` / token 用量 / 思维链长度 / 正文。
  和 `--info` 的区别：`--info` 只调 `GET /models`，那只证明 **key 有效**，不证明**能拿到答案**。
- 大模型调用**失败不会白屏**：自动降级为离线摘录，答案和引用照常给，
  底部如实标注原因（例：`⚠️ 大模型调用失败，已自动降级为离线摘录…`）。

### 6.2 语义向量通道（解决"大白话提问"漏答）

DeepSeek 官方**没有** embedding 接口，需第三方：

```powershell
$env:SILICONFLOW_API_KEY = "sk-xxxx"     # 硅基流动 BAAI/bge-m3，需实名认证，价格页标为免费
```

## 7. 局限与已知问题（主动讲，比被问出来好）

1. **离线抽取式回答的固有短板（最重要的一条）**：降级模式只做"原文摘录 + 全局排序"，
   **不会改写、不会归纳**。所以遇到这两种情况会显得不够聪明：
   - FAQ 类文档里答案是"答：不能。"这种 4 字结论句（太短会被丢弃），
     实际摘出的是下一句"……因此不符合申请条件"——**语义正确、但不是最凝练的那句**；
   - "由三部分构成"这类**引导句 + 列表**结构，摘出来的是引导句本身，列表内容排在后面。

   → 这不是推理错误，而是"抽取式"这种生成方式的能力上限：
     句子级选择无法重组信息。**接上 LLM 后（`--llm`）这类问题会自然消失**，
     因为 LLM 做的是"读完整段后重新组织语言"。
     换句话说：`--llm` 是产品形态，离线抽取是**保证永不白屏的兜底**。
2. **仍有 31.2% 的可答题被拒答**，集中在两类：① 提问用词与文档用词不一致
   （问"最多能借几本书"，文档写的是"可借册数"）；② 复合问句（"要什么材料、什么时候交、
   科研怎么计分"）证据分散在多个小节。检索本身命中了正确文档（Hit@3=100%），
   但字面重叠不足导致置信度低于阈值。
   → 对症解法是启用 §6.2 的语义向量通道（治①）与查询分解（治②）。
3. **评测集只有 22 题、2 篇文档**：指标有方差，阈值标定存在过拟合风险
   （`sweep.py` 在 5×11 的参数网格上挑最优，本身就有一点点"挑到测试集上"的成分）。
   生产做法：500+ 题、交叉验证、按类别分层看指标。
4. **关键事实覆盖率 62.5%** 是"关键事实命中"这一廉价代理指标，不是 LLM 判官。
   好处是断网可复现、零成本；代价是无法评估"回答是否流畅、是否答非所问"。
   生产环境该补 RAGAS 的 Faithfulness / Answer Relevancy。
   （它此前报 81.2%，是因为拒答正文里的候选片段被当成了"命中"——见 §4 的口径修正。）
5. **规模**：当前 63 块、暴力遍历毫秒级。到 10 万块需要倒排索引落盘 + ANN（HNSW/IVF）；
   `retriever.py` 的接口不用改，换实现即可。

## 10. 改动后如何确认没退化（回归清单）

改检索或抽取逻辑后，**不要靠眼看答案**（我吃过这个亏：直觉上"更周到"的改动让覆盖率从
79.3% 掉到 69.0%，用的是当时尚未修正的口径），跑这五条：

```powershell
python -m unittest discover -s tests   # ⓪ 回归测试：修过的 bug 不许回来
python demo_check.py    # ① 演示用例是否条条正确（含"必须拒答"的两条）
python ask.py --eval    # ② 核心指标是否守住：硬答率必须为 0
python bench.py         # ③ 消融实验：这项改动到底有没有用（严格 / 端到端两个口径都要看）
python sweep.py         # ④ 改了分词/检索后，阈值要重新标定（分数分布变了）
```

判断标准：**硬答率 > 0 视为失败**（幻觉不可接受）；在这个前提下再比拒答准确率与覆盖率。
另外 ⓪① 必须看**退出码**——这个项目上一次翻车（见 `docs/known-issues.md`），
根因就是"没有任何命令的失败被检查"。
