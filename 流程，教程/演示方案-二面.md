# 二面 · 项目演示方案

> 目标：让对方看到**你在假期变强了**，而不是看到项目多难。
> 因此演示的重点**不是"它能答对"，而是"我知道它什么时候会答错、以及我怎么发现的"**。

---

## 一、上台前 5 分钟（必做，别省）

| # | 动作 | 通过标准 |
| --- | --- | --- |
| 1 | 终端 `cd` 到项目目录 | 提示符在当前路径 |
| 2 | `python demo_check.py` | **10 条全过** |
| 3 | `python -m unittest discover -s tests -v` | **Ran 9 tests … OK** |
| 4 | 双击 `run_web.bat`，浏览器先开着 | 页面能打开、能问一句 |
| 5 | **截图备份**（见下） | 三张图放在桌面 |

### 截图备份（万一现场跑不起来，这就是你的救命稻草）

1. `demo_check.py` 10 条全过的画面
2. `ask.py --eval` 的指标画面
3. 9 条测试全绿的画面

> **上台前先跑一遍 `demo_check.py`，不是给别人看，是给自己上保险。**
> 如果 10 条里有不过的 —— **别硬上台演示，改成讲文档 + 看截图。**

---

## 二、演示顺序（约 6 分钟）

| # | 时长 | 做什么 | 想让他们看到 |
| --- | --- | --- | --- |
| **1** | 20s | `git log --oneline -14` | **假期 8 个提交**，标题全是"修 bug / 补测试 / 写文档" |
| **2** | 20s | `python -m unittest discover -s tests -v` | **9 条测试**，尤其点出两条测试名 |
| **3** | 10s | `python demo_check.py` | 演示用例 10/10，**先说"这一步是防我现场翻车的"** |
| **4** | 3min | `python ask.py --web`，问 5 个问题 | 答得准 + **敢拒答** + **敢承认误拒** |
| **5** | 20s | `python ask.py --eval` | 22 题指标自己跑出来，含 **62.5%** 这个"不好看但真实"的数字 |
| **6** | 1min | 打开 `docs/known-issues.md` | 4 个 bug 的复盘——**这是"学到了什么"的证据** |

### 第 1 步的话术（重点，别跳过）

> "这是我假期的提交记录。你们可以看到，**8 个提交里没有一个是在加新功能**
> ——全是修 bug、补测试、写文档。这个假期我没做新东西，我把旧东西拆开看了一遍。"

### 第 2 步的话术（点出这两条测试名）

> "9 条测试里我最想说的是这两条：
> 一条叫'**同义词表里每一条都必须真的能触发**'——因为我发现那张表里有 16 个词条是永远不会生效的死代码；
> 另一条叫'**拒答必须计 0 分**'——这条防的是我原来那个'拒答刷满分'的 bug。"

## 三、演示时要问的 5 个问题

**每个问题先说出你预期的结果，再敲回车。** 这一步很关键——它说明你**知道**系统会怎么答，而不是碰运气。

| # | 问题 | 预期 | 你要说的一句话 |
| --- | --- | --- | --- |
| 1 | 南海校区宿舍晚上几点关门？周五周六会延后吗？ | 23:00 / 23:30 | "先来一个简单的，看它引用原文。" |
| 2 | 旷课多少节会被警告处分？ | 12 学时 | "这个问法跟文档用词不一样，看它能不能找到。" |
| 3 | 南海校区图书馆闭馆前提前多久清场？ | 10 分钟 | "换个主题。" |
| 4 | **南海校区游泳池的开放时间和收费标准是什么？** | **拒答** | ⭐ 见下方高光话术 |
| 5 | 四六级报名要交多少钱？ | **拒答（误拒）** | ⭐ 见下方加分话术（可选） |

### ⭐ 第 4 题：高光时刻（一定要问）

> **"大多数人的演示只会演示'它能答对'。我给你们看一个反的——
> 这个问题我们学校的资料里根本没有，它多少钱、几点开，我都不知道。
> 我要看的是：**它会编一个，还是直接说不知道。**"**
>
> *（敲回车 → 显示拒答）*
>
> "它说'资料中没有找到足够相关的内容'。**这就是我整个项目里最在意的一个指标：硬答率。**"

### ⭐ 第 5 题：加分项（可选，你敢就用）

> **"我再给你们看一个它答不出来的。"**
>
> *（问"四六级报名要交多少钱？" → 拒答）*
>
> "这题的答案文档里**明明有**，是 36 块。但它没找到，因为我的问法是'多少钱'，
> 文档里写的是'费用：笔试 36 元/次'，**字面对不上**。
>
> 这个叫**误拒**，我现在的误拒率是 **31.2%**。我没有把它藏起来，
> 因为我知道它为什么发生——**要解决它，正确顺序是先把评测集从 22 题扩到 100 题以上，而不是直接调参数。**"

> ⚠️ 第 5 题是双刃剑。**如果你紧张，就跳过它。** 1–4 步已经足够。

## 四、翻车回退方案（按顺序试）

| 情况 | 怎么办 |
| --- | --- |
| `--web` 打不开 | 改成命令行：`python ask.py "南海校区宿舍晚上几点关门？"` |
| python 命令报错 | **不要现场调试。** 换成："代码在我机器上跑得通，我直接讲文档。"然后开截图 |
| 完全没有网络 | **不影响**。这个项目本来就是离线优先，大模型只是可选增强 |
| 被问的问题你答不上来 | "这个我不会。我的理解到 X 为止，往下我没验证过。"**——然后停下，别补话** |

## 五、高频追问 & 安全回答

| 他可能问 | 你怎么答 |
| --- | --- |
| **"这些代码是你写的吗？"** | **"不是，核心代码是 AI 写的。"** 然后立刻接："我假期做的是**验证、找 bug、加测试**——8 个提交全是这些。" |
| "你 Python 到什么程度？" | "**能看懂函数和流程，从零写还不行。** 我假期写的不是核心算法，是测试和文档。" |
| "你怎么发现那些 bug 的？" | "我对照 README 一条条验证它承诺的东西。第一个 bug 就是这么撞出来的——**README 让我跑的命令直接崩了**。" |
| "4 个 bug 里你觉得哪个最重要？" | "**拒答刷覆盖率那个。** 因为它不只让数字虚高，还让我那个挑参数的脚本一直在奖励'更爱拒答'的参数——**它污染的是我的判断，不是代码。**" |
| "你为什么把 81.2% 改成 62.5%？" | "**因为原来那个算法是错的。** 拒答的时候系统会把原文片段贴出来，覆盖率是在整段回答上做匹配的，所以'答不出来'拿了满分。改成真实口径就掉下来了。" |
| "你为什么不直接调参数把指标调好看？" | "因为那套评测集是我刚建的。**拿它调参数，它就变成测试集了。** 我报的是一组真正的样本外指标。" |
| "接下来打算做什么？" | "三件事：**①** 写一个脚本，跑完评测去核对 README 的数字，对不上就报错；**②** 把评测集从 22 题扩到 100 题以上；**③** 最后才谈调参数。" |

---

## 六、最后三条纪律

1. **演示前先跑 `demo_check.py`。** 它存在的唯一意义就是防你现场翻车。
2. **每个问题先说预期，再回车。** 这是"我知道"和"我碰运气"的分界线。
3. **主动说出不会的地方。** 你是大一，答不出来是正常的；**装懂被追问穿才是致命的。**
