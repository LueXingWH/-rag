# 已知问题与面试风险

> 记录日期：2026-09-22　记录人：AI 协作会话
> 起因：为准备 20 天后的社团面试，对仓库做了一次"README 声称 vs 实际可复现"的核对。

---

## 摘要：面试前必须处理的 3 件事

`面试讲解稿.md` §2 要求你在面试官面前现场执行 `python ask.py --eval`，并宣称**硬答率 0%**。

**在修复前，那条命令会打印 `没料却硬答率：50.0%`。** 这不是小数点问题——"硬答率"是你整个项目最核心的安全指标，现场出现 50% 会直接推翻你的项目叙事。

下面三条按严重程度排列。

---

## 问题 1｜`ask.py --eval` 直接崩溃 ✅ 已修复

**现象**

```
FileNotFoundError: [Errno 2] No such file or directory:
  '...\my__ai\data\eval_set.json'
```

**根因**：`ask.py` / `bench.py` / `calibrate.py` / `sweep.py` 四处都把评测集默认路径写成了
`data/eval_set.json`，而文件实际在 **`data/logs/eval_set.json`**。
`data/eval_set.json` 在全部 git 历史中**从未存在过**（`git log --all -- data/eval_set.json` 无输出）。

也就是说：README 首推的"一条命令复现指标"从某个时间点起就已经失效，而没人发现——**因为没有任何自动化在跑它**。

**修复**：四个文件的默认路径改为 `data/logs/eval_set.json`；README 的目录树同步更正。

---

## 问题 2｜README 的指标与当前评测集对不上 ⚠️ 未修复

| 指标 | README §4 声称 | 实测（当前仓库） |
| --- | --- | --- |
| 评测集规模 | **22 题**（16 可答 + 6 应拒答） | **10 题**（8 可答 + 2 应拒答） |
| 语料 | **44 块 / 7 篇** | 9 篇（南海校区 2 篇 + `无用` 7 篇） |
| Hit@1 | 100% | **87.5%** |
| MRR | 1.000 | **0.917**（默认语料）/ 0.938（仅南海） |
| 拒答准确率 | 81.8% | 90.0% |
| **硬答率** | **0.0%** | **50.0%** |
| 关键事实覆盖率 | 82.3% | 100% |

评测集在提交 `8670bb4`（"南海校区评测集与演示用例更新为08/09语料"）中被换成 10 题，
但 README 的 §4 指标表和"四次迭代轨迹"没有同步更新。

**这意味着 README 里那组数字，目前无法用仓库里任何一条命令复现。**
对一个主打"指标可复现"的项目来说，这是最伤的一类问题。

**待决策**（属于项目叙事，需要作者自己定）：
- 是把 README 指标改成当前实测值？
- 还是重建一个 22 题规模的评测集，让结论恢复统计意义（10 题确实太少）？

## 问题 3｜默认语料包含名为"无用"的旧目录，反过来破坏了核心指标 ⚠️ 未修复

**根因**：`data/corpus/` 下同时存在两个目录：

- `南海校区/`（08、09）—— 当前有效语料
- `无用/`（01–07）—— 目录名直接写着"无用"，是早期编造的示例语料

`ask.py` 的默认 `--corpus` 是 `data/corpus`（**递归加载**），所以 **7 篇废弃语料仍参与检索**。
`demo_check.py` 则显式只加载 `data/corpus/南海校区`。

**两套语料 → 同一问题给出两个结论**：

| 语料范围 | 拒答准确率 | **硬答率** | MRR |
| --- | --- | --- | --- |
| 仅 `南海校区/`（demo_check 的口径） | 100.0% | **0.0%** | 0.938 |
| `data/corpus`（`ask.py --eval` 的默认口径） | 90.0% | **50.0%** | 0.917 |

具体触发用例：`nu01`「南海校区游泳池的开放时间和收费标准是什么？」

- 仅南海语料：`conf=0.30` → **拒答** ✅
- 默认语料：`conf=0.49` → **硬答** ❌

多出来的 7 篇文档改变了 IDF 与证据分布，把这个本该拒答的问题推过了 0.42 的阈值。

**结论**：README 声称的"硬答率 0%"，**只在南海语料范围内成立**。

**待决策**（三选一，需要作者判断）：
1. 把默认 `--corpus` 改成 `data/corpus/南海校区`；
2. 把 `无用/` 移出 `data/corpus/`（例如 `data/archive/无用/`）——**目录名已经承认它无用了**；
3. 保留现状，但明确在 README 里声明"指标基于南海语料"。

---

## 附：为什么这些问题之前没被发现

1. **没有任何自动化在核对 README 与实测值** —— `demo_check.py` 只校验 10 个**手工挑选**的演示用例，它们全部通过；它不读 README，也不跑完整评测集。
2. **`demo_check.py` 与 `ask.py --eval` 用不同语料** —— 一个绿、一个红，但因为没人同时跑，矛盾一直没暴露。
3. **评测集从 22 题缩到 10 题没有同步文档** —— 数字变了，叙述没变。

> **这三条本身就是最好的面试素材。** 一个能说清"我的自动化测试为什么漏掉了这个 bug"的候选人，比一个宣称"我的指标全绿"的候选人可信得多。
