# 选择「用 AI 派」，放弃「做 AI 派」

**Status**: accepted（2026-09-22）

本仓库同时承载作者的学习路线文档（`docs/roadmap.md`）。这里记录该路线中**最难逆转**的一个决定。

在"进一步学习 AI"这个目标下，存在两条几乎不重叠的路径：

- **(甲) 用 AI 派** —— 把 AI 当工具做出东西。要 Python 工程能力、交付能力、领域知识。
- **(乙) 做 AI 派** —— 理解并改进模型。要线代/概率/微积分、PyTorch、读论文。

**决定：走 (甲)。** 作者已证实的能力（接口逆向、工程判断、驱动 AI 交付）在 (甲) 中全部复用；
每天 1.5 小时的时间预算下，(乙) 四年只能到"看懂论文摘要"，而 (甲) 足够做到"独立交付一个真产品"。

## Considered Options

- **(甲) 用 AI 派** —— 选中。
- **(乙) 做 AI 派** —— 被拒。既有资产复用率接近 0，且时间预算不支持。
- **(丙) 两条都要** —— 被拒。每天 1.5 小时，两条路都走等于两条路都不走。

## Consequences

- **正面**：学习内容收窄为「Python 真功夫 + 工程能力 + 驱动 AI」，资源清单因此可以裁剪
  （见 `docs/roadmap.md` §5，其中明确排除了李沐《动手学深度学习》、CS231n、吴恩达 ML）。
- **负面**：不学深度学习的代价是**无法判断模型能力的边界**，只能使用别人交付的工具。
  缓解方式：养成读官方文档的习惯，并主动收集"模型在这里失效了"的案例——**而不是去学反向传播**。
- **可逆性**：不锁死读研。数学跟学校课程走、成绩考好，保研期权保留。
  若日后转为 (乙)，需补的正是今天刻意跳过的数学与训练循环，成本约 6–12 个月。
- **对既有项目的影响**：`campus_rag` 的价值定位随之明确——
  它是「**会用 AI 交付**」的证据，**不是**「懂 AI」的证据。
  这也是为什么它的 README 把"设计取舍"和"评测闭环"讲得比技术实现更重。
