## 0 · 一页纸全貌

```
                     ┌───────────── 只做一次（启动时）─────────────┐
  data/corpus/*.md ──▶ data.py ──▶ 63 个「块」──▶ retriever 建索引
                     │  按标题切块      每块带标题路径    ├─ BM25 倒排表
                     │  表格表头回填                   └─ TF-IDF 字符向量
                     └──────────────────────────────────────────────┘

                     ┌───────────── 每次提问 ─────────────────────┐
 你的问题 ──▶ text.py 分词 ──▶ retriever.search()                  │
                              ├─ 通道A  BM25 词法      → 排名       │
                              ├─ 通道B  字符3gram TF-IDF → 排名     │
                              ├─ 通道C  embedding（可选）→ 排名      │
                              ├─ 通道D  同义词扩展（权重0.4）→ 排名  │
                              └─ RRF 融合（只用排名）→ 前 5 块       │
                                        │                          │
                                        ▼                          │
                              engine._confidence() → 0~1 分         │
                                        │                          │
                          ┌─────────────┴─────────────┐            │
                     < 0.42│                           │≥ 0.42     │
                          ▼                           ▼            │
                    【拒答】直接返回           有 LLM？             │
                    "资料中没有相关内容"        ├是→【LLM 生成】接地提示词+[n]引用
                                               └否→【抽取式降级】原文摘录
                     └──────────────────────────────────────────────┘
                                        │
                                        ▼
                              Answer 对象 ──▶ CLI / 网页 / 评测 / JSONL 日志
```

**一句话**：语料切成块 → 两条通道找候选 → RRF 合并 → 算一个置信度 → 够格才答，不够就拒答。

### 文件职责（11 个文件，按依赖顺序）

```
config.py ── 所有参数（阈值/块大小/模型名）
text.py ──── 分词：中文 bigram+单字、英文词干、字符 3-gram
data.py ──── 读文件 → 按标题切块 → 表格表头回填 → Chunk 对象
retriever.py ─ BM25 + TF-IDF + RRF + 同义词扩展
engine.py ── ★核心：置信度闸门 + LLM生成 + 抽取式降级
llm.py ───── urllib 调 OpenAI 兼容接口（可选、可失败）
web.py+ui.html ─ 标准库 HTTP 服务 + 单文件前端
evaluate.py ─ 22 题评测，6 个指标
qa_logger.py ─ 每次问答追加一行 JSONL（旁路，失败不影响主流程）
ask.py ───── CLI 入口（ask/chat/eval/web/info 五种模式）
```

**关键结构**：`text / data / retriever` 三层**零第三方依赖、零网络**——这就是"离线优先"的技术含义。

## 1 · 数据准备（启动时做一次）

```
08-南海校区校规校纪问答.md (291 行, 38 块)
09-南海校区通知公告问答.md (167 行, 25 块)          → 共 63 块
```

### 1.1 怎么切块（`data.chunk_markdown` [L127](campus_rag/data.py#L127)）

```
原始 Markdown
  # 手册标题
  ## 宿舍管理与生活秩序          ← 碰到标题就把攒的正文存成一块
  ### 门禁与作息（南海校园）        并把「标题路径」记下来
  - 宿舍大门每日 06:00 开门……
  ## 考勤与请假
  ...
        │
        ▼
  ① 按标题切语义块       ② 块>480字就按句子切，尾部留 80 字重叠      ③ 太短的碎片并回上一块
        │
        ▼
  Chunk(chunk_id, source, title, heading, text, position)
  例：08-...md#3 | heading="手册 > 宿舍管理与生活秩序 > 门禁与作息（南海校园）" | 209 字
```

**为什么带标题路径？** 两个用途：① UI 显示"哪个文件·哪一节"；② 检索时标题命中算**强信号**（`retriever.py` 里把标题词词频 ×3 计入 BM25）。

### 1.2 表格表头回填（全项目最值钱的一处修正）

原始表格的数据行里**没有**"情形""处分"这些词——它们只在表头：

```
输入：  | 情形 | 处分 |
        |---|---|
        | 替考、组织作弊… | 开除学籍 |

直接切 → 数据行 = "| 替考、组织作弊… | 开除学籍 |"   ← "处分"一次都没出现 → 检索漏检

回填后 → 表格表头：情形 | 处分
        表格行：情形：替考、组织作弊…，处分：开除学籍   ← 每行自带语义 ✅
```

代码：[`data._coalesce_tables`](campus_rag/data.py#L65)。判断"是不是真表格"看有没有 `|---|---|` 分隔行。

### 1.3 分词（`text.tokenize` [L86](campus_rag/text.py#L86)）

因为不用 jieba（要 `pip install`，违反零依赖），改用**相邻两字切分**：

```
"南海校区宿舍晚上几点关门？"
  ↓ bigram（主）                        ↓ unigram（辅，兜底召回）
南海 海校 校区 区宿 宿舍 舍晚 晚上       南 海 校 区 宿 舍 晚 上 几 点 关 门
上几 几点 点关 关门
```

| 为什么要单字 | 语料写"奖励标准：8000 元"，用户问"金额是多少"——两者**没有任何共同 bigram**，直接漏检。单字 IDF 天然极低，只兜底、不污染排序。 |
| --- | --- |
| 为什么两套切法 | `tokenize` 给 BM25 用（有"词"的概念，IDF 有效）；`char_ngrams` 给向量通道用（无视词边界）。**切法不同才有融合价值**。 |

## 2 · 检索：两条通道 + RRF 融合

`HybridRetriever.search` [L321](campus_rag/retriever.py#L321)

```
                     ┌── 通道A：BM25 词法（权重1.0）
                     │   擅长精确术语/数字："12 学时" "FM75" "15 公里"
                     │   脆弱点：同义改写
问题 ──┬─ tokenize ─┤
       │             ├── 通道B：字符3gram TF-IDF 余弦（权重1.0）
       │             │   擅长模糊改写；对精确数字不如A
       │             │
       │             ├── 通道C：embedding 语义（权重1.2，需配 key）
       │             │
       │             └── 通道D：同义词扩展 BM25（权重0.4）
       │                  "几本"→"可借册数"；只提召回，★不参与置信度
       │                        │
       └────────────────────────┴──▶ RRF 融合 ──▶ 覆盖率加成 ──▶ 前 5 块
```

### 2.1 BM25（[L108](campus_rag/retriever.py#L108)）：三个机制解决三个问题

```
① 词越常见越不值钱  → 乘 IDF:  log(1 + (N-df+0.5)/(df+0.5))
② 出现10次≠相关10倍 → 词频饱和: f*(k1+1) / (f + k1*(1-b+b*len/avg_len))
③ 长文档不该占便宜  → 上面的 b 项做长度归一化        k1=1.2, b=0.75（Lucene 默认值）
```

倒排表 `postings`：`"旷课" → [块12, 块14]`。搜索时直接拿这两个块算分，不遍历全部。
**标题加权很廉价**：`counts[标题词] += 2 * c`，只多 3 行代码。

### 2.2 RRF 融合（[L261](campus_rag/retriever.py#L261)）：为什么不用分数？

```
问题：BM25 分数是 65.88，余弦是 0.0889 —— 量纲完全不同，加权求和毫无意义。

解法：score = Σ w / (k + rank)      k=60，只用排名
      排第1 → 1/61 = 0.0164
      排第2 → 1/62 = 0.0161        ← 差距极小，所以"多通道共识" > "单通道第一"
```

**代价**：RRF 分数没有绝对意义（实跑第1名 0.0328、第2名 0.0323，几乎一样），
所以**不能拿它比阈值** → 这就是 `engine.py` 必须另算一套置信度的原因。

## 3 · 闸门：这道题该不该答？（核心）

`RagEngine.answer` [L254](campus_rag/engine.py#L254) → `_confidence` [L94](campus_rag/engine.py#L94)

### 3.1 置信度公式

```
                  ┌─ idf_cov  IDF加权联合覆盖率（前5块）  权重 0.52  ← 主信号
                  ├─ focus    第1名领先第2名的幅度        权重 0.10
  base = 0.52·idf_cov + 0.10·focus + 0.38·lex              ← lex = BM25分压缩到0~1
                  └─ lex      BM25 绝对分（x/(x+14) 饱和）权重 0.38
                     │
   × (1 − 0.30 × rare_share)     稀有词惩罚：信息量落在"全语料只出现≤7次"的词上 → 打折
   × (1 − 0.85 × oov_share)      OOV 惩罚：查询里语料从未出现的概念占比 → 打折
   × 0.70                        （若查询总信息量 ≤ 4.5：全是高频虚词）→ 再打折
                     │
                     ▼
             confidence ∈ [0,1]  ──▶  与 answer_threshold=0.42 比较
```

### 3.2 五个信号分别防什么

| 信号 | 防的失败模式 | 关键点 |
| --- | --- | --- |
| `idf_cov` | **虚词当证据** | 朴素覆盖率（命中数/总数）会把"什么/多少"算成证据 → 没料也硬答。按 IDF 加权后只有实词算数 |
| `oov_share` | **问了个语料里没有的概念** | 唯一能区分"用词不同"（能答）和"概念不存在"（该拒答）的非词法依据 |
| `rare_share` | **冷门词巧合命中** | IDF 的特性是越稀有越值钱，于是"水温"这种只出现1次的词碰巧命中会抬高覆盖率。加一层惩罚抵消它 |
| `focus` | **多篇文档都沾边** | 第1名和第2名打平 = 检索在"打平"，常意味着问题超出语料范围 |
| `lex` | **分数量纲不可比** | BM25 原始分无上界（见过 5 ~ 65），用 `x/(x+14)` 压到 0~1 |

### 3.3 实跑：一次作答 vs 一次拒答

| 问题 | idf_cov | rare | oov | max_lex | **conf** | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 宿舍几点关门？周五周六延后吗？ | 0.810 | 0.584 | 0.190 | 65.88 | **0.561** | ✅ 作答 |
| 旷课多少节会被警告处分？ | 0.954 | 0.657 | 0.046 | 47.33 | **0.680** | ✅ 作答 |
| 游泳池的开放时间和收费标准？ | 0.468 | 0.467 | **0.352** | 17.08 | **0.296** | ❌ 拒答 |

看第三行：`oov_share=0.352` 就是"游泳池"被抓出来的地方——**三成概念我从没见过**。
再看第二行：`rare=0.657` 高达 0.657 却仍答对，因为原始覆盖率 0.954 实在太高。
**惩罚是"打折"，不是"一票否决"。**

### 3.4 阈值 0.42 是怎么来的（实跑扫描）

| 阈值 | 拒答准确率 | 漏答率 | **硬答率** | 覆盖率 |
| --- | --- | --- | --- | --- |
| 0.25 | 77.3% | 6.2% | 66.7% | 84.4% |
| 0.35 | 81.8% | 12.5% | 33.3% | 78.1% |
| **0.42** | **77.3%** | **31.2%** | **0.0%** ← 第一次归零 | 62.5% |
| 0.50 | 50.0% | 68.8% | 0.0% | 31.2% |
| 0.60 | 36.4% | 87.5% | 0.0% | 12.5% |

> 覆盖率一列是**修掉"拒答刷分"之后**的值（见 §6.4）：拒答一律计 0，
> 所以阈值越高、拒答越多，覆盖率越低。修之前这几格是 84.4 / 84.4 / **81.2** / 56.2 / 46.9，
> 看起来"提到 0.42 覆盖率几乎不降"——那是假象，降的全是被拒答的题。

```
硬答率(左) ────┐
  100%|█        │  阈值越低 → 越敢答 → 硬答率飙升
   67%|██       │  阈值越高 → 越保守 → 漏答率飙升
   33%|███      │
    0%|████████─┼──★ 0.42：硬答率第一次归零的最小阈值
      └─────────┘     再往上只是白牺牲漏答率
       0.25  0.42  0.60
```

⚠️ **两组分布是重叠的**（实测）：可答题 `n10` 只有 0.227，比三道应拒答题还低。
所以**不存在完美分开两组的阈值**，只能在重叠区里选偏向安全侧的边界。

### 3.5 三重拒答防线

```
① 闸门（生成之前）    conf < 0.42 → 直接拒答，不把材料送给模型     ← 确定性、可评测
② 接地提示词          提示词第4条："如果资料完全不支持，直接回答'资料中没有相关内容'"
③ 引用强制            "每个结论后必须标注 [1]" → 说过的话必须能核对
```

## 4 · 两种回答形态

```
                          conf ≥ 0.42
                              │
              ┌───────────────┴───────────────┐
        有 LLM key？                     没有 / 调用失败
              │                               │
              ▼                               ▼
    ┌──────────────────┐          ┌──────────────────────┐
    │ mode="llm"       │          │ mode="extractive"    │
    │ 严格接地提示词    │          │ 原文摘录，绝不改写    │
    │ 每句带 [n] 引用   │          │ 所以不可能产生幻觉    │
    │ = 产品形态        │          │ = 永不白屏的兜底      │
    └──────────────────┘          └──────────────────────┘
```

### 4.1 抽取式选句（`_extractive` [L161](campus_rag/engine.py#L161)）三个讲究

| 讲究 | 原因 |
| --- | --- |
| **数字额外加权** `+0.05×数字个数` | 政策类问题的答案往往就是一个数字（"8000 元""30 天"） |
| **问句降权 ×0.2** | FAQ 文档里的问句和用户问题字面几乎一样，会霸占第1名，但它**只重复了问题、没给答案** |
| **话题短语按匹配长度给分** | "国家奖学金"节匹配4字、"国家励志奖学金"节只沾到"奖学金"3字，前者必须得分更多 |

选句打分复用 BM25 的两个成熟机制（词频饱和 + 句长归一化），而不是自己拍系数。

**为什么只从 3 个块里挑句子？** 实测（端到端口径，拒答算没覆盖）：
2 块 53.8% → 3 块 **65.4%** → 4/5/6 块仍是 65.4%。2 块明显不够，3 块之后不再有收益，
而"答了的题答得准不准"（严格口径）在 3 块就到位了（77.8% → **94.4%** 后持平）。
排名靠后的块里混进了"说得对但没回答这个问题"的句子。

### 4.2 抽取式的固有短板（已知）

```
问：宿舍晚上几点关门？
答：（离线抽取式回答：以下为资料原文摘录…）
    [2] **周日至周四 23:00** 关门熄灯，**周五、周六及法定节假日 23:30** 关门。  ← ✅ 正确
    [1] 周日至周四 23:00 关，周五、周六及法定节假日 23:30 关。                ← ✅ 正确
    [3] - 寒暑假及法定节假日暂停报销，报销日遇节假日顺延一周。                 ← ❌ 噪声
    [1] **问：宿舍晚上几点关门？                                              ← ❌ 噪声（问句）
```

**这说明两件事**：① 前两行是对的，能核对；② 抽取式不会归纳，所以会有噪声——
**接上 LLM（`--llm`）后这类问题自然消失，因为 LLM 做的是"读完重新组织语言"。**
所以 `--llm` 是产品形态，离线抽取是**保证永不白屏的兜底**。

## 5 · Web Demo 怎么转

```
浏览器                    web.py (148行, 标准库 http.server)        engine.py
  │  GET /                     │                                    │
  │ ─────────────────────────▶ │ 读 ui.html 返回                     │
  │  GET /api/info              │ 返回 {chunks:63, docs:[...]}        │
  │ ─────────────────────────▶ │                                    │
  │  POST /api/ask              │                                    │
  │  {"question":"宿舍几点关门"} │ _build_payload()                   │
  │ ─────────────────────────▶ │ ─────────────────────────────────▶ │
  │                            │       检索→置信度→闸门→生成          │
  │                            │ ◀───────────────────────────────── │
  │                            │ log_answer() 记一行 JSONL           │
  │  ◀───────────────────────── │ JSON                               │
  │  renderCard() 渲染          │                                    │
  │  ★点答案里的 [2] → 滚动到第2条引用并高亮 → 你能直接看到原文        │
```

| 设计点 | 原因 |
| --- | --- |
| 端口 8000~8019 依次尝试 | 你不用去查"谁占了我的端口" |
| `with _LOCK` 串行化 | 纯 Python 检索是 CPU 密集，多线程抢 GIL 会让延迟抖动 |
| 前端 `esc()` 转义 | 资料内容是外部输入，不转义就是 XSS 漏洞 |
| 没有 npm / CDN / 构建 | 断网也能跑；面试现场最怕"再装一个依赖" |

**最有价值的交互**：引用编号可点击 → 让"是否正确"从**信任问题**变成**核对问题**。

## 6 · 怎么证明它真的行

### 6.1 评测集与六个指标（`evaluate.run_eval` [L90](campus_rag/evaluate.py#L90)）

```
22 题 = 8 直问 + 6 改写 + 2 多跳 + 6 应拒答
       └────────── 16 可答 ──────────┘   └ 必须拒答 ┘
```

| 指标 | 本次实测 | 回答什么问题 |
| --- | --- | --- |
| **Hit@3** | **100%** | 答案所在文档被召回了吗？→ **检索是 RAG 的上限** |
| Hit@1 | 81.2% | 正确文档排第一的比例 |
| MRR | 0.896 | 平均倒数排名（"排第2"也拿 0.5 分，比 Hit@1 细腻） |
| 拒答准确率 | 77.3% | 该拒/该答判断对的比例（唯一同时惩罚两类错误） |
| **硬答率** | **0.0%** | ★ **最关键的指标**：资料里没有却硬答的比例 |
| 关键事实覆盖率 | 62.5% | 答案里含期望数字/术语的比例（**拒答=计 0**，见 §6.4） |
| 漏答率 | 31.2% | 有资料却拒答（闸门的**代价**，不是反面） |

**分类别看才能定位问题**：

| category | n | Hit@3 | 拒答准 | 覆盖率 |
| --- | --- | --- | --- | --- |
| direct（直问） | 8 | 100% | 75% | 75% |
| paraphrase（改写） | 6 | 100% | 67% | 50% | ← 拖后腿
| multi_hop（多跳） | 2 | 100% | 50% | 50% | ← 拖后腿
| unanswerable（应拒答） | 6 | — | 100% | 0%（拒答不计覆盖） |

→ 检索没有丢失任何可答题（Hit@3 全 100%），**漏答集中在改写与多跳两类**。

### 6.2 五条回归命令（改代码后按顺序跑）

```powershell
python -m unittest discover -s tests -v   # ⓪ 回归测试：曾经修过的 bug 不许回来 → 退出码非0=失败
python demo_check.py    # ① 10条演示用例条条正确？含2条必须拒答 → 退出码非0=失败
python ask.py --eval    # ② 核心指标守住没？★硬答率必须为 0

```

**判断标准**：**硬答率 > 0 视为失败**（会误导学生）；在这个前提下再比拒答准确率与覆盖率。
另外 ①②③ 都要看**退出码**——这个项目上一次翻车，就是因为"没有任何命令的失败被检查"。

### 6.3 三个实验脚本在验证什么

| 脚本 | 回答的问题 | 本次结论 |
| --- | --- | --- |
| `sweep.py` | 55 种 (阈值 × evidence_k) 哪个最好？ | 推荐 0.40/3，比当前 0.42/5 指标更好——**但刻意不采纳**（见下） |
| `calibrate.py` | 两组分布的中间在哪？ | 0.42 是"0硬答"的最小值；两组在 0.23~0.42 重叠 |
| `bench.py` | 这个改动真的有用吗？ | `extractive_chunks` 3 是拐点（2 块 53.8% → 3 块 65.4% 后持平）；严格/端到端双口径防"多拒答刷分" |

## 9 · 面试讲法：向上追问三层

> 第1层"这是什么" → 第2层"为什么这么写（替代方案是什么）" → 第3层"去掉/换掉会怎样"。
> **"我不知道，但我可以这样验证"是允许的答案；装懂不是。**

| 决策 | 第2层（为什么不用替代方案） | 第3层（去掉会怎样） |
| --- | --- | --- |
| **bigram+单字**代替 jieba | jieba 精度高但要 pip install；项目要求断网也能跑。这也是 Lucene `CJKBigramFilter` 的官方做法 | 去掉单字：文档里的双字词无法被单字查询匹配（"金额" vs"奖励标准"），直接漏检 |
| **两通道 + RRF** | 也可以加权求和，但 BM25 是 65.88、余弦是 0.0889，量纲不可比；RRF 只用排名免去归一化 | RRF 丢掉了分数信息（第1名0.0164 vs 第2名0.0161），所以**不能拿它当置信度** |
| **闸门前置于生成** | 也可以让模型自己看资料后判断，但模型有"必须给出像样回答"的倾向，实测会硬答 | 早期版本没闸门：**硬答率 83.3%**（早期语料实测）→ 当前 0.0% |
| **IDF 加权置信度** | 朴素覆盖率把"什么/多少"算成证据 → 没料也硬答（v0→v1 的核心修正） | 副作用是稀有词 IDF 虚高（"水温"只出现1次），所以又加了稀有词惩罚——**两层互相制衡** |
| **表格表头回填** | 数据行里没有"可借册数""借期"这些词，它们全在表头；表头和数据行被切到不同块必然漏检 | 不做：图书馆借阅类问题会被误判为"证据不足"而拒答 |
| **0.42 不再调优** | sweep 建议 0.40/3，指标更好，但评测集是刚建的——用它调参它就变成训练集了 | 正确顺序：先扩到 100+ 题 → 分层看 → 最后调参 |

### 最容易被追问的 5 个细节

1. **`evidence_k`(5) 和 `top_k`(4) 为什么分开？** → 多跳问题证据常在第4~6名，用生成块的窄视野判断会误拒。实测：`evidence_k=1` 漏答率 62.5%，`=5` 降到 31.2%。
2. **RRF 里 `k=60` 是什么？** → 平滑常数。让第1名和第2名差距变小，从而让"多通道共识"比"单通道第一"更重要。
3. **OOV 惩罚怎么算？** → 语料里不存在的查询词按 2.0 虚拟 IDF 计入总量，然后 `base ×= 1 − 0.85×oov_share`。
4. **评测为什么不用 LLM 当裁判？** → 评测必须断网可复现、零成本、结果稳定。生产环境应补 RAGAS。
5. **语料扩到 10 万块哪里先崩？** → `BM25`/`TfidfVector` 是内存全表算分，会从 3ms 涨到秒级。换倒排索引落盘 + ANN；**`retriever.py` 接口不用改，换实现即可**。
